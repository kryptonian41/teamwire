# Task: build AFK mode for teamwire

teamwire needs AFK runs: a lead runs one team on one task while the user is away, with no questions to the user until a report is written.

The design and build plan are in `docs/design/2026-10-19-afk-mode.md`. Read all of it first. Schema version 5 (`team.afk_budget_ends_at`) is already committed, as the plan's "Precondition" says.

End state: everything that sections 5 and 6 of the design describe exists and is tested.

- `teamwire afk start` (section 5.2).
- The AFK hold in the lead's Stop hook (section 5.3).
- The budget and the model table in launch (section 5.4).
- Close and status for AFK teams (section 5.5).
- The AFK skill with the agreed content of section 6, installed the way the other skills are (section 5.6).

Use the command names, flags, refusal codes and messages that the design gives. Where the design leaves a detail open, decide it and say what you decided in your final message.

## Names the design does not give

Use these names, which the rest of the code will rely on:

- `teamwire afk start` refuses with these codes, in addition to the ones the design names:
  - `no_lead_session` when no lead harness session id reaches the command.
  - `no_lead_process` when the platform needs a sleep hold and the lead's process cannot be found. Nothing is created.
  - `afk_already_running` when the calling session already leads an open AFK team.
  - `doctor_failed` when a doctor check fails. The refusal names the check.
- Crate `teamwire-report` exports `afk_hold_notes(home: &Path, session: &SessionId, platform: &dyn Platform, clock: &dyn Clock) -> Vec<String>`, beside `teams_without_watch` and `watch_missing_note`. It returns the AFK hold notes for the open AFK teams that `session` leads, when nothing will wake the lead: no open team the session leads has both a working member and a live watch lease.
- Crate `teamwire-store`: `create_afk_team` takes a fourth parameter, `create_afk_team(at, team: &NewTeam, budget_ends_at, extra: &serde_json::Value)`. The keys of `extra` are merged into the data of the `team.created` event. `teamwire afk start` passes `{"lead_cwd": <the lead's working directory>}`.
- Crate `teamwire-watch`: `StatusView` gets `afk: Option<AfkView>`, `None` for a team that is not an AFK run. `AfkView` has the fields `budget_ends_at: Timestamp`, `seconds_left: u64` (zero once the budget is spent), `spent: bool` and `decisions: u32` (the number of `D<n>` entries in `afk/decisions.md`). `status --json` writes the same field names.
- `teamwire teams --json` gives each team an `afk_budget_ends_at` key: a timestamp string for an AFK team, `null` otherwise. The dashboard's zod schemas in `ui/src/shared/teamwire.ts` accept the `afk` object and this key, and also accept older output without them.

+/// Why close must refuse the AFK team whose directory is `team_dir`, or
+/// `None` when its report has every heading.
+pub(crate) fn refusal(team_dir: &Path) -> Option<String> {
+    let path = team_dir.join("afk").join("REPORT.md");
+    let text = match std::fs::read_to_string(&path) {
+        Ok(text) => text,
+        Err(e) => {
+            let why = if e.kind() == std::io::ErrorKind::NotFound {
+                "is missing".to_owned()

+                format!("cannot be read ({e})")
+            };
+            return Some(format!(

+                path.display(),
+                AFK_REPORT_HEADINGS.join(", ")
+            ));
+        }
+    };
+    let missing = missing_headings(&text);
+    (!missing.is_empty()).then(|| {
+        format!(
+            "{AFK_REPORT_INCOMPLETE}: {} lacks the headings: {}",
+            path.display(),
+            missing.join(", ")
+        )
+    })

+/// The text of a Markdown ATX heading line (`#` to `######`, then a space),

+fn floor(kind: MemberKind) -> (&'static str, &'static str) {

+        MemberKind::Reviewer | MemberKind::Closer => ("opus", "xhigh"),

+/// A Claude model's rank by family name, so `claude-opus-4-1` reads as opus.
+fn model_rank(model: &str) -> Option<usize> {
+    let m = model.to_ascii_lowercase();
+    ["haiku", "sonnet", "opus"]
+        .iter()
+        .position(|family| m.contains(family))

+fn effort_rank(effort: &str) -> Option<usize> {
+    ["low", "medium", "high", "xhigh", "max"]

+/// One warning per member below the AFK table. An unset or unknown model or
+/// effort counts as below it, because the harness default may be lower. A
+/// Codex member's model names are not Claude's, so only its effort is read.
+pub(crate) fn model_warnings(members: &[PlannedMember], warnings: &mut Vec<String>) {
+    for m in members {
+        let (want_model, want_effort) = floor(m.kind);
+        let mut below = Vec::new();
+        if m.harness.as_str() != "codex" {
+            let model = m.spec.model.as_deref();
+            if model.and_then(model_rank) < model_rank(want_model) {

+            }
+        }

+        if effort.and_then(effort_rank) < effort_rank(want_effort) {
+            below.push(format!("effort {}", effort.unwrap_or("unset")));
+        }

+                "role {}: {} is below the AFK table for a {} ({want_model}, {want_effort})",
+                m.spec.role,

+# ADR 0025: An AFK run is one team led by a Claude Code session that never waits
+
+Status: accepted, 2026-10-23. The design brief is
+`docs/design/2026-10-19-afk-mode.md`.
+
+## Context
+
+A user wants to type one task, walk away, and come back to a result and a
+report. Members already work with no human present: they start with their
+permission prompts off, and their contract says nobody is watching. The lead
+does not. A lead that ends a turn on a question to the user is never woken
+again. The main skill tells the lead to ask the user its open questions, to
+tell the user about `TEAM-STALLED`, and to ask before a push. The Mac can
+sleep during planning, because launch takes the sleep hold only when the
+first member starts. Nothing limits how long a lead keeps re-planning. And a
+lead that does the research, planning and review itself fills its context
+during a long run.
+
+## Decision
+
+1. **A run starts with a second plugin skill, `/teamwire:afk <task>`.**
+   `examples/skills/afk/SKILL.md` is rendered by `teamwire install` into the
+   plugin as `skills/afk/SKILL.md`, beside the main skill, and stamped like
+   it. The skill reads the main skill first and lists only what AFK changes;
+   the main skill has one line pointing at it. Doctor checks it as part of
+   the plugin's files, so a missing or older AFK skill fails the
+   `teamwire plugin` check as the main skill does. Only a Claude Code lead
+   has AFK mode. A Codex lead keeps today's behaviour.
+2. **One AFK run is one team.** Its state lives where every team's does:
+   `$TEAMWIRE_HOME/teams/<team>/`, with its row in that team's `team.db`.
+   The run's shared files (`task.md`, `understanding.md`, `plan.md`,
+   `decisions.md`, `briefs/`, the wave specs and `REPORT.md`) sit in the
+   team directory's `afk/` folder, so close archives them with no new code.
+   Every member joins that team with `teamwire launch --add`.
+3. **The team row marks the run.** One nullable column, schema version 5:
+   `team.afk_budget_ends_at`. A value means the team is an AFK run, and the
+   value is when its wall-clock budget ends.
+4. **`teamwire afk start --team NAME --title TITLE --task FILE [--budget 8h]`
+   opens the run before any member exists.** It runs from the shell, in
+   this order, and stops at the first failure:
+   - it finds the lead session as launch does (ADR 0006). It refuses with
+     `no_lead_session` outside a lead session, `no_lead_process` when the
+     lead's process cannot be found for the sleep hold, and
+     `afk_already_running` when this session already leads an open AFK
+     team;
+   - it checks the name and title with launch's rules, and refuses with
+     launch's own codes, including a name already taken;
+   - it runs doctor's launch checks (`launch_checks` in `doctor.rs`): disk,
+     host, harness, plugin and `.worktrees/` ignored. These leave out the
+     per-team database checks, because another team's broken database does
+     not stop this run, and FAIL when there is no host, because no member
+     could start. Any FAIL refuses with `doctor_failed`; a warning is
+     printed and does not refuse;
+   - it creates the team with no members, copies the task file to
+     `afk/task.md` byte for byte, and takes or reuses the sleep hold through
+     launch's own code, so close releases it as today.
+5. **The lead's Stop hook holds the stop of an AFK lead that nothing will
+   wake.** It holds when the session leads an open AFK team,
+   `stop_hook_active` is false, the turn is not a subagent's, and no team of
+   this session has a started member without a completion and a live watch.
+   The note tells the lead to decide instead of asking, write the decision
+   to `afk/decisions.md`, and add the reporter when the work is done. It
+   holds once per stop chain, like the existing hold.
+6. **The budget stops new code, not the ending.** Past
+   `afk_budget_ends_at`, launch refuses each new `implementer` with
+   `refused: afk_budget_spent` and accepts every other kind, so the run can
+   still review, verify and report. Launch warns once per member of an AFK
+   team whose model or effort is below the skill's table.
+7. **Close ends a run, after the report.** Close refuses an AFK team whose
+   `afk/REPORT.md` is missing or lacks one of the eight headings with
+   `refused: afk_report_incomplete`. The headings are `##` headings with
+   these exact names, and a leading number such as `## 1. ` is accepted:
+   `What you asked`, `What I understood`, `The result`, `Verified`,
+   `Decisions made for you`, `Not done, and why`, `Risks`, `Cost`. A
+   `--role` removal is unaffected.
+8. **Status is the run's status.** `teamwire status <team>` shows one more
+   line for an AFK team: the budget end, the time left and the number of
+   decisions in `afk/decisions.md`; `--json` gets an `afk` object.
+   `teamwire teams` marks an AFK team with `afk`, and its `--json` carries
+   `afk_budget_ends_at`.
+9. **Members do the work, and the lead decides.** The lead picks members
+   from the skill's profiles (analyst, scout, planner, plan reviewer,
+   implementer, reviewer, closer, reporter) and records its roster as `D1`
+   in `afk/decisions.md` before the first launch. Five things are fixed:
+   never wait, protect the lead's context, the closer once code exists, the
+   reporter, and the boundaries (no push, pull request, merge into the base
+   branch, branch deletion, `teamwire install` or `cargo install`). The
+   planner is an investigator writing only under `afk/`, so no new member
+   kind is needed. Member contracts do not change.
+10. **Models.** Implementers and investigators run on `opus` at `high`;
+    reviewers, the plan reviewer and the closer at `xhigh`; the planner at
+    `xhigh`; `max` for at most one member with a hard task. Every
+    `deadline_s` is 1.5 times the normal value.
+
+## Considered options
+
+- A separate AFK home: a state directory such as `$TEAMWIRE_HOME/afk/<run>/`
+  with its own record of runs. Rejected: every reader of team state (status,
+  teams, watch, close, reopen, metrics, the dashboard) would need a second
+  place to look, and the hold, archive and Stop hook would need a second
+  owner. One team per run needs one column.
+- Several teams per run, one per phase. Rejected: the hold, the archive, the
+  metrics and the Stop hook's check would spread over several rows.
+- An `afk finish` command. Rejected: close already ends a team in the safe
+  order and releases the hold.
+- An `afk status` command. Rejected: the run is a team, so `teamwire status`
+  shows it.
+- Starting with `teamwire launch` and a first member. Rejected: the Mac could
+  sleep during planning, before any member exists.
+- A counter that holds the lead's stop more than once. Rejected: it would
+  hold forever, or need state the read-only hook does not write, and a lead
+  with its own background command must be able to stop.
+- A token budget. Rejected by the user: a wall-clock budget only.
+- A refusal of every member kind past the budget. Rejected: the reporter and
+  the closer must still run, and new code is what drags a run on.
+- The lead doing research, planning and review itself, as the main skill has
+  it below four members. Rejected: a long run fills the lead's context, and
+  the lead decides worse.
+- A new member kind for the planner. Rejected: an investigator may not edit
+  repository files, and `afk/` is outside the repository.
+- Telling members about AFK. Rejected: their contract already assumes no
+  human; only their briefs change, carrying decisions instead of questions.
+- Reading the lead's permission mode in `afk start`. Rejected: the command
+  runs from Bash and cannot see it, so the skill has the lead read its own
+  context.
+
+## Consequences
+
+- The user starts with `/teamwire:afk <task>` in a session run with
+  `claude --permission-mode bypassPermissions` (or auto mode), and gets a
+  local integration branch and `afk/REPORT.md` in the team's archive. The
+  user pushes it.
+- An older binary opens an AFK team's version 5 database read only and
+  refuses to write it (ADR 0015).
+- A lead that stops twice with nothing running is stuck: the second stop
+  passes because `stop_hook_active` is true. The hold also misses a
+  background command the lead started itself. The design accepts this, and
+  `teamwire status` shows the AFK team open with no working member.
+- A Claude usage limit pauses the lead and every member. AFK mode cannot
+  work around it; the report's `Cost` section shows the gap afterwards.
+- A closed lid still sleeps a Mac, whatever the hold does. `afk start` and
+  the skill tell the user to keep the lid open and the machine on power.
+- After `cargo install`, the user runs `teamwire install` again to get the
+  AFK skill, as for any skill change.

+# AFK runs with teamwire
+
+You lead a teamwire team on one task, and nobody will answer you until the
+run ends. Load the `teamwire:teamwire` skill first: in this plugin it is
+`../teamwire/SKILL.md`, with `../teamwire/reference.md` beside it. This file
+lists only what changes. Where the two disagree, this file wins.

+## The one rule
+
+Never wait for a person. When you would ask the user something, answer it
+yourself with the answer you would have recommended, write it into the
+decision log, and carry on. A turn that ends on a question to the user ends
+the run, because nothing will wake you again. Step 1 is the only place you
+may stop for the user.
+
+## 1. Preflight, while the user may still be at the keyboard
+
+1. Check that your context says bypass permissions mode or auto mode is
+   active. If it does not, tell the user to restart the session with
+   `claude --permission-mode bypassPermissions`, and stop.
+2. Write the user's task, word for word, to a file. Pick a team name and a
+   title from the task. Run
+   `teamwire afk start --team <name> --title <title> --task <file>`, with
+   `--budget` only when the user named a time limit. On a refusal or a FAIL
+   line, tell the user what failed and stop.

+   ends, and: "Keep the lid open and the machine on power." Then carry on
+   with the run (section 2 onward) in the same turn. Do not wait for an
+   answer.

+Never start a second team for this run.

+what order.

+  it, then merge again. Do not resolve conflicts yourself.
+- `TEAM-STALLED` is yours to handle, not the user's. Run `teamwire status`,
+  read the pane, and replace the member once. If the replacement stalls too,
+  cut the unit and report it.
+- `teamwire status <team>` shows the time left in the budget. Launch the
+  last implementer no later than two thirds of the way through it, so the
+  review, the closer and the report still fit. Past the budget, launch
+  refuses new implementers. Finish what is running, verify it, and have the
+  reporter list the rest as not done.
+
+## 7. Report and close
+
+Add the `reporter` with the paths of whichever of these exist:
+`afk/task.md`, `afk/understanding.md`, `afk/plan.md`, `afk/decisions.md`,
+the closer's report, and the team's `reports/` directory. It runs
+`teamwire metrics <team>` for the cost, and gathers every member's
+**Decisions I made** list. It writes `afk/REPORT.md` with these eight
+sections, in this order. Each is a Markdown `##` heading with exactly this
+name, because close looks for these names (a leading number, as in
+`## 1. What you asked`, is also accepted):
+
+1. `## What you asked`: the task, quoted.
+2. `## What I understood`: the end state from `understanding.md`.
+3. `## The result`: the branch, its base commit, the commits, and how to try
+   it.
+4. `## Verified`: each command, where it ran, and its exit code.
+5. `## Decisions made for you`: the ones that most change the result, with
+   a pointer to `decisions.md`.
+6. `## Not done, and why`.
+7. `## Risks`: what you could not check, and what the reviewer or closer
+   flagged that is still open.
+8. `## Cost`: wall time, and tokens per member.
+
+Run `teamwire close <team>`. Close refuses until the report has every
+heading, archives the team with the `afk/` files, keeps the branches and
+releases the sleep hold. When close refuses, reprompt the reporter with the
+missing headings. Then call `PushNotification` with the archived report's
+path if you have that tool.
+
+A run always ends with a report. When something fails that nobody can fix,
+have the reporter write up what exists. A partial result with an honest
+report is the goal. A session waiting for a person is the failure.
