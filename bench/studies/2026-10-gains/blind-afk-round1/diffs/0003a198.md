# Task: build AFK mode for teamwire

teamwire needs AFK runs: a lead runs one team on one task while the user is away, with no questions to the user until a report is written.

The design and build plan are in `docs/design/2026-10-19-afk-mode.md`. Read all of it first. Schema version 5 (`team.afk_budget_ends_at`) is already committed, as the plan's "Precondition" says.

End state: everything that sections 5 and 6 of the design describe exists and is tested.

- `teamwire afk start` (section 5.2).
- The AFK hold in the lead's Stop hook (section 5.3).
- The budget and the model table in launch (section 5.4).
- Close and status for AFK teams (section 5.5).
- The AFK skill with the agreed content of section 6, installed the way the other skills are (section 5.6).

Use the command names, flags, refusal codes and messages that the design gives. Where the design leaves a detail open, decide it and say what you decided in your final message.

## Names the design does not give

Use these names, which the rest of the code will rely on:

- `teamwire afk start` refuses with these codes, in addition to the ones the design names:
  - `no_lead_session` when no lead harness session id reaches the command.
  - `no_lead_process` when the platform needs a sleep hold and the lead's process cannot be found. Nothing is created.
  - `afk_already_running` when the calling session already leads an open AFK team.
  - `doctor_failed` when a doctor check fails. The refusal names the check.
- Crate `teamwire-report` exports `afk_hold_notes(home: &Path, session: &SessionId, platform: &dyn Platform, clock: &dyn Clock) -> Vec<String>`, beside `teams_without_watch` and `watch_missing_note`. It returns the AFK hold notes for the open AFK teams that `session` leads, when nothing will wake the lead: no open team the session leads has both a working member and a live watch lease.
- Crate `teamwire-store`: `create_afk_team` takes a fourth parameter, `create_afk_team(at, team: &NewTeam, budget_ends_at, extra: &serde_json::Value)`. The keys of `extra` are merged into the data of the `team.created` event. `teamwire afk start` passes `{"lead_cwd": <the lead's working directory>}`.
- Crate `teamwire-watch`: `StatusView` gets `afk: Option<AfkView>`, `None` for a team that is not an AFK run. `AfkView` has the fields `budget_ends_at: Timestamp`, `seconds_left: u64` (zero once the budget is spent), `spent: bool` and `decisions: u32` (the number of `D<n>` entries in `afk/decisions.md`). `status --json` writes the same field names.
- `teamwire teams --json` gives each team an `afk_budget_ends_at` key: a timestamp string for an AFK team, `null` otherwise. The dashboard's zod schemas in `ui/src/shared/teamwire.ts` accept the `afk` object and this key, and also accept older output without them.

+        }
+        cmd.output().unwrap()
+    }

+//! An AFK run ends with its report (AFK design section 5.5): close refuses
+//! an AFK team until `afk/REPORT.md` holds every heading the AFK skill

+
+/// The eight headings of the AFK skill's report, in its order.
+pub const AFK_REPORT_HEADINGS: [&str; 8] = [
+    "What you asked",
+    "What I understood",
+    "The result",
+    "Verified",
+    "Decisions made for you",
+    "Not done, and why",
+    "Risks",
+    "Cost",
+];
+
+/// The refusal for an AFK team whose report is missing or lacks a heading.
+pub(crate) fn report_refusal(team_dir: &Path, team: &TeamRow) -> Option<String> {
+    team.afk_budget_ends_at?;
+    let path = team_dir.join("afk").join("REPORT.md");
+    let Ok(text) = std::fs::read_to_string(&path) else {
+        return Some(format!(
+            "afk_report_incomplete: {} is missing; have the reporter write it",
+            path.display()
+        ));
+    };
+    let found: Vec<String> = text.lines().filter_map(heading).collect();
+    let missing: Vec<&str> = AFK_REPORT_HEADINGS
+        .into_iter()
+        .filter(|h| !found.iter().any(|f| f.eq_ignore_ascii_case(h)))
+        .collect();
+    (!missing.is_empty()).then(|| {
+        format!(
+            "afk_report_incomplete: {} lacks the heading(s) {}; reprompt the reporter",
+            path.display(),
+            missing.join(", ")
+        )
+    })
+}

+/// The text of a Markdown heading line, without its `#`s, a leading number
+/// such as `1.`, bold marks or a trailing colon: `## 3. **The result**`
+/// reads as `The result`.
+fn heading(line: &str) -> Option<String> {
+    let rest = line
+        .trim_start()
+        .strip_prefix('#')?
+        .trim_start_matches('#')
+        .trim();
+    let rest = rest
+        .trim_start_matches(|c: char| c.is_ascii_digit())
+        .trim_start_matches(['.', ')'])
+        .trim()
+        .trim_matches('*')
+        .trim()
+        .trim_end_matches(':')
+        .trim_matches('*')
+        .trim();
+    Some(rest.to_owned())
+}

+/// Section 5.4 of the AFK design for a launch into an AFK team: past the
+/// budget an implementer is refused, and a member below the model table is
+/// warned about. A team that is not an AFK run is unaffected.
+pub(crate) fn launch_rules(
+    env: &ValidateEnv<'_>,
+    existing: Option<&Existing>,
+    members: &[PlannedMember],
+    errors: &mut Vec<SpecError>,
+    warnings: &mut Vec<String>,
+) {
+    let Some(ends) = existing.and_then(|e| e.team.afk_budget_ends_at) else {
+        return;
+    };
+    let spent = env.clock.now() >= ends;
+    for m in members {
+        let role = m.spec.role.as_str();
+        if spent && m.kind == MemberKind::Implementer {
+            errors.push(SpecError::new(
+                Some(role),
+                Some("kind"),
+                "afk_budget_spent",
+                format!(
+                    "the AFK budget ended at {ends}; add reviewers, investigators or the closer \
+                     to finish what is running, and no new implementer"
+                ),
+            ));
+        }
+        if let Some(why) = below_table(m.kind, m.spec.model.as_deref(), m.spec.effort.as_deref()) {
+            warnings.push(format!("{role}: {why}"));
+        }
+    }
+}

+/// How effort levels rank; a level not listed is not judged.
+const EFFORTS: [&str; 5] = ["low", "medium", "high", "xhigh", "max"];
+
+/// Why a member's model or effort is below the AFK table, if it is: opus at
+/// `high` for implementers and investigators, at `xhigh` for reviewers and
+/// the closer. A missing value counts as below, because the harness default
+/// may be lower.
+pub(crate) fn below_table(
+    kind: MemberKind,
+    model: Option<&str>,
+    effort: Option<&str>,
+) -> Option<String> {
+    let want = match kind {
+        MemberKind::Implementer | MemberKind::Investigator => "high",
+        MemberKind::Reviewer | MemberKind::Closer => "xhigh",
+    };
+    let rank = |e: &str| EFFORTS.iter().position(|x| *x == e);
+    let low_model = model.is_none_or(|m| {
+        let m = m.to_ascii_lowercase();
+        m.contains("sonnet") || m.contains("haiku")
+    });
+    let low_effort = effort.is_none_or(|e| rank(e).is_some_and(|r| Some(r) < rank(want)));
+    (low_model || low_effort).then(|| {
+        format!(
+            "model {} at effort {} is below the AFK table, which wants opus at {want} for a {kind}",
+            model.unwrap_or("(default)"),
+            effort.unwrap_or("(default)")
+        )
+    })
+}

+# ADR 0025: An AFK run is one team whose lead never waits for a person
+
+Status: accepted, 2026-10-23. Design and build plan:
+`docs/design/2026-10-19-afk-mode.md`.
+
+## Context
+
+Members already work with nobody present: they start with their harness's
+approval bypass, and their contract tells them to decide and record each
+choice. The lead does not. A lead turn that ends on a question to the user
+ends the run, because nothing wakes the lead again. The Mac can also sleep
+while the lead plans, because launch takes the sleep hold only when the
+first member starts, and nothing limits how long a lead keeps re-planning.
+
+## Decision
+
+1. **One AFK run is one ordinary team.** The nullable column
+   `team.afk_budget_ends_at` (schema version 5) marks it and says when its
+   wall-clock budget ends. Its state lives in `$TEAMWIRE_HOME/teams/<team>/`
+   like every team, and the run's shared files go in that directory's `afk/`
+   folder, so close archives them with no new code. Every member joins with
+   `teamwire launch --add`, which accepts an AFK team that has no members
+   yet.
+2. **`teamwire afk start` creates the team before any member exists.** It
+   refuses outside a lead session (`no_lead_session`), for a session that
+   already leads an open AFK team (`afk_already_running`), for a name or
+   title launch would refuse, on any `FAIL` of the doctor checks a launch
+   needs (`doctor_failed`), and when the platform holds sleep and the lead's
+   process cannot be found (`no_lead_process`). Each refusal creates nothing.
+   It then copies the task to `afk/task.md` and takes the sleep hold through
+   launch's `ensure_hold`, so close releases it as for any team.
+3. **The lead's Stop hook holds the stop for an open AFK team when nothing
+   will wake the lead**: no open team the session leads has both a working
+   member and a live watch lease. It holds once per stop chain
+   (`stop_hook_active`), joins its note with the "no watch" note, writes
+   nothing and keeps its time budget.
+4. **Past the budget, launch refuses each new implementer**
+   (`afk_budget_spent`) and accepts every other kind, so the run can still

+

+run ends. Read the teamwire skill first. This file lists only what changes,
+and where the two disagree, this file wins.
+
+## The one rule
+
+Never wait for a person. When you would ask the user something, answer it
+yourself with the answer you would have recommended, write it into the
+decision log, and carry on. A turn that ends on a question to the user ends
+the run, because nothing will wake you again. Step 1 is the only place you
+may stop for the user.

+## 1. Preflight, while the user may still be at the keyboard
+

+   active. If it does not, tell the user to restart the session with
+   `claude --permission-mode bypassPermissions`, and stop.
