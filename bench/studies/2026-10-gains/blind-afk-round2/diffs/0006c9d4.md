# Task: build AFK mode for teamwire

teamwire needs AFK runs: a lead runs one team on one task while the user is away, with no questions to the user until a report is written.

The design and build plan are in `docs/design/2026-10-19-afk-mode.md`. Read all of it first. Schema version 5 (`team.afk_budget_ends_at`) is already committed, as the plan's "Precondition" says.

End state: everything that sections 5 and 6 of the design describe exists and is tested.

- `teamwire afk start` (section 5.2).
- The AFK hold in the lead's Stop hook (section 5.3).
- The budget and the model table in launch (section 5.4).
- Close and status for AFK teams (section 5.5).
- The AFK skill with the agreed content of section 6, installed the way the other skills are (section 5.6).

Use the command names, flags, refusal codes and messages that the design gives. Where the design leaves a detail open, decide it and say what you decided in your final message.

## Names the design does not give

Use these names, which the rest of the code will rely on:

- `teamwire afk start` refuses with these codes, in addition to the ones the design names:
  - `no_lead_session` when no lead harness session id reaches the command.
  - `no_lead_process` when the platform needs a sleep hold and the lead's process cannot be found. Nothing is created.
  - `afk_already_running` when the calling session already leads an open AFK team.
  - `doctor_failed` when a doctor check fails. The refusal names the check.
- Crate `teamwire-report` exports `afk_hold_notes(home: &Path, session: &SessionId, platform: &dyn Platform, clock: &dyn Clock) -> Vec<String>`, beside `teams_without_watch` and `watch_missing_note`. It returns the AFK hold notes for the open AFK teams that `session` leads, when nothing will wake the lead: no open team the session leads has both a working member and a live watch lease.
- Crate `teamwire-store`: `create_afk_team` takes a fourth parameter, `create_afk_team(at, team: &NewTeam, budget_ends_at, extra: &serde_json::Value)`. The keys of `extra` are merged into the data of the `team.created` event. `teamwire afk start` passes `{"lead_cwd": <the lead's working directory>}`.
- Crate `teamwire-watch`: `StatusView` gets `afk: Option<AfkView>`, `None` for a team that is not an AFK run. `AfkView` has the fields `budget_ends_at: Timestamp`, `seconds_left: u64` (zero once the budget is spent), `spent: bool` and `decisions: u32` (the number of `D<n>` entries in `afk/decisions.md`). `status --json` writes the same field names.
- `teamwire teams --json` gives each team an `afk_budget_ends_at` key: a timestamp string for an AFK team, `null` otherwise. The dashboard's zod schemas in `ui/src/shared/teamwire.ts` accept the `afk` object and this key, and also accept older output without them.

+## AFK runs
+
+To leave a task running while you are away, start Claude Code with
+`claude --permission-mode bypassPermissions` and type
+`/teamwire:afk <task>`. The lead runs `teamwire afk start --team NAME
+--title TITLE --task FILE [--budget 8h]`, which creates the team, saves the
+task and keeps the Mac awake, then plans, builds, reviews and verifies with a
+team and never waits for you. It refuses to start with `no_lead_session`,
+`no_lead_process`, `afk_already_running` or `doctor_failed`. Past the budget,
+`teamwire launch` refuses new implementers (`afk_budget_spent`), and
+`teamwire close` refuses until `afk/REPORT.md` has every heading
+(`afk_report_incomplete`).
+
+The result is a local branch `afk/<team>` and the report. Nothing is pushed.
+`teamwire status` shows the budget, the time left and the number of
+decisions made for you (`--json`: an `afk` object with `budget_ends_at`,
+`seconds_left`, `spent`, `decisions`), and `teamwire teams --json` has
+`afk_budget_ends_at`. Keep the lid open and the machine on power: a closed
+lid still sleeps a Mac.

+//! The AFK report check (design 5.5): an AFK team cannot be closed until
+//! `<team dir>/afk/REPORT.md` has the eight headings of the AFK skill.
+//!
+//! A heading is a line that starts with one or more `#`; its text, after
+//! dropping `**` markers, case and a leading number such as `1.`, must start
+//! with the heading name. A `#` line inside a code fence counts like any
+//! other line (shortcut: no fence tracking, the report is prose).
+
+use std::path::Path;
+
+use teamwire_store::TeamRow;
+
+/// The headings, in the order the reporter writes them.
+const HEADINGS: [&str; 8] = [
+    "What you asked",
+    "What I understood",
+    "The result",
+    "Verified",
+    "Decisions made for you",
+    "Not done, and why",
+    "Risks",
+    "Cost",
+];
+
+/// The refusal for an AFK team whose report is missing or incomplete, or
+/// `None` for a team that is not AFK or whose report is complete.
+pub(crate) fn report_refusal(home: &Path, team: &TeamRow) -> Option<String> {
+    team.afk_budget_ends_at?;
+    let path = home
+        .join("teams")
+        .join(team.name.as_str())
+        .join("afk")
+        .join("REPORT.md");
+    let Ok(text) = std::fs::read_to_string(&path) else {
+        return Some(format!(
+            "afk_report_incomplete: {} is missing; have the reporter write it",
+            path.display()
+        ));
+    };
+    let missing = missing_headings(&text);
+    (!missing.is_empty()).then(|| {
+        format!(
+            "afk_report_incomplete: {} lacks the heading(s): {}",
+            path.display(),
+            missing.join("; ")
+        )
+    })
+}

+fn missing_headings(text: &str) -> Vec<&'static str> {
+    let titles: Vec<String> = text.lines().filter_map(heading_text).collect();
+    HEADINGS
+        .into_iter()
+        .filter(|name| {
+            let name = name.to_lowercase();
+            !titles.iter().any(|t| t.starts_with(&name))
+        })
+        .collect()
+}
+
+/// The normalised text of a `#` line: lower case, no `**`, no leading number.
+fn heading_text(line: &str) -> Option<String> {
+    let rest = line.trim_start().strip_prefix('#')?.trim_start_matches('#');
+    let text = rest.replace("**", "").to_lowercase();
+    let text = text.trim();
+    let digits = text.trim_start_matches(|c: char| c.is_ascii_digit());
+    let text = if digits.len() < text.len() {
+        digits.trim_start_matches(['.', ')'])
+    } else {
+        text
+    };
+    Some(text.trim().to_owned())

+pub(crate) fn afk_view(

+    now: Timestamp,

+    let ends = budget_ends_at?;

+    })

+pub(crate) fn count_decisions(text: &str) -> u32 {
+    let count = text
+        .lines()
+        .filter(|line| {
+            let digits = line
+                .strip_prefix('D')
+                .map(|rest| rest.trim_start_matches(|c: char| c.is_ascii_digit()));
+            digits.is_some_and(|after| {
+                after.len() < line.len() - 1 && after.starts_with(char::is_whitespace)
+            })
+        })
+        .count();
+    u32::try_from(count).unwrap_or(u32::MAX)

+# ADR 0025: An AFK run is one ordinary team with a budget
+
+Status: accepted, 2026-10-19.
+
+## Context
+
+The user wants to type one task, walk away, and find a local branch and one
+report on return. Members already assume no human is present (bypass
+permissions, a contract that says nobody is watching, trust prompts answered
+by launch). The lead is what blocks. It ends a turn with a question and
+nothing wakes it again, it asks for approvals, it may push, and a Mac can
+sleep during planning before any member exists. The design is in
+`docs/design/2026-10-19-afk-mode.md`.
+
+## Decision
+
+1. **An AFK run is one team.** Its `team` row has a new nullable column,
+   `afk_budget_ends_at` (schema version 5). A value means the team is an AFK
+   run and is when its budget ends. Every member joins with
+   `teamwire launch --add`; a run never uses a second team.
+   - Beaten: a separate `afk/` home under `$TEAMWIRE_HOME` with its own
+     database and readers. Status, teams, close, the archive, metrics, the
+     Stop hook and the dashboard would each need a second code path to find
+     it. A run in the ordinary team directory is found by all of them
+     unchanged.
+   - Beaten: an `afk` boolean plus a separate budget field. One column
+     carries both facts.
+2. **`teamwire afk start --team NAME --title TITLE --task FILE [--budget 8h]`
+   creates the team before any member exists.** It finds the lead session as
+   launch does, runs the doctor checks a launch needs, creates the team row
+   with the budget, copies the task to `afk/task.md` and takes the sleep
+   hold at once. It refuses with `no_lead_session`, `no_lead_process`,
+   `afk_already_running` or `doctor_failed`. Beaten: letting the first
+   `launch` create the team; the Mac could sleep during planning, and the
+   task would not be on disk.
+3. **The run's files live in `$TEAMWIRE_HOME/teams/<team>/afk/`.** Close
+   already archives the whole team directory, so they reach the archive with
+   no new code. The path avoids `reports/`, which belongs to members.
+4. **The lead's Stop hook holds the stop of an AFK team once per stop chain.**
+   It holds when the team is open, `stop_hook_active` is false, and nothing
+   will wake the lead (no started member without a completion that also has a
+   live watch lease). Beaten: a counter of holds, which would hold forever
+   or need extra state; a lead with a background command of its own must be
+   able to stop.
+5. **The budget is checked in launch.** Past `afk_budget_ends_at`, launch
+   refuses a new `implementer` with `afk_budget_spent` and accepts every
+   other kind, so the run can still review, verify and report. Default
+   budget: `8h`. Beaten: a hard kill at the deadline, which loses unreported
+   work.
+6. **A run ends with `teamwire close`.** Close refuses an AFK team whose
+   `afk/REPORT.md` is missing or lacks a required heading, with
+   `afk_report_incomplete`. Beaten: an `afk finish` command, which would
+   duplicate close's safe order and the hold release.
+7. **`teamwire status` is the run's status.** It shows an afk line, and
+   `--json` an `afk` object `{budget_ends_at, seconds_left, spent,
+   decisions}`. `teamwire teams --json` has `afk_budget_ends_at`. Beaten: an
+   `afk status` command.
+8. **Nothing leaves the machine.** The result is a local integration branch
+   that passed the full gate, plus one report. The run never pushes, opens a
+   pull request or merges into the base branch.
+9. **The lead's behaviour is a second skill, `/teamwire:afk`.** Install
+   renders `examples/skills/afk/SKILL.md` into the plugin beside the main
+   skill, and doctor checks it with the plugin's other files. Members and
+   their contract do not change. Claude Code leads only.
+
+## Consequences
+
+- A team with a null `afk_budget_ends_at` behaves exactly as before.
+- Older binaries read a version 5 database read-only (ADR 0015).
+- A closed lid still sleeps a Mac; `afk start` tells the user to keep the lid
+  open and the machine on power.
+- A usage limit ends the run early; the Stop hook cannot help a session that
+  cannot run. The archive keeps what exists.

+## The one rule
+
+Never wait for a person. When you would ask the user something, answer it
+yourself with the answer you would have recommended, write it into the
+decision log, and carry on. A turn that ends on a question to the user ends
+the run, because nothing will wake you again. Step 1 is the only place you
+may stop for the user.
+
+## 1. Preflight, while the user may still be at the keyboard
+
+1. Check that your context says bypass permissions mode or auto mode is
+   active. If it does not, tell the user to restart the session with
+   `claude --permission-mode bypassPermissions`, and stop.
+2. Write the user's task, word for word, to a file. Pick a team name and a
+   title from the task. Run
+   `teamwire afk start --team <name> --title <title> --task <file>`, with
+   `--budget` only when the user named a time limit. On a refusal or a FAIL
+   line, tell the user what failed and stop.
+3. Reply once with the team name, the report path, the time the budget
+   ends, and: "Keep the lid open and the machine on power." Then start step 2
+   in the same turn. Do not wait for an answer.
+
+The run is this one team. Every member you add later joins it with
+`teamwire launch --add`. Never start a second team for this run.
+
+## 2. What every run must have
+
+You choose the team for each task. These five things hold in every run, and
+nothing in the task changes them:
+
+1. You never wait for a person (the one rule above).
+2. You protect your own context (section 3).
+3. Once code exists, the `closer` runs. It runs every claimed check and the
+   repository's full gate on each branch and on the joined branch, and
+   records each exit code. It is the only member that turns the team's
+   claims into evidence before the user reads the report.
+4. A `reporter` writes `afk/REPORT.md` (section 7). Close refuses the team
+   until the report has every heading.
+5. The boundaries hold: never push, open a pull request, merge into the base
+   branch, delete a branch, or run `teamwire install` or `cargo install`.
+   Never act on a team this session does not lead.
+
+Everything else is yours to decide: which members to add, how many, and in
+what order.
+
+## 3. Your context is the run's scarcest resource
+
+You decide. Members research, plan, review, verify and write. Every file you
+read stays in your context for the rest of the run, and a lead with a full
+context decides worse. So:
+
+- Give research, planning, review, verification and report-writing to
+  members. Do one yourself only when it is smaller than writing its brief,
+  and never reading more than one or two short files.
+- Pass work by path. A brief or a reprompt names files. Never paste a
+  report, a diff or a log into a message.
+- Read a member's result line and the summary at the top of its report. Read
+  further only when two members contradict each other, and then only the
+  lines in dispute.
+- Never read a raw diff, check output or a gate log. The closer reads those.
+- Members read each other's files by path. A planner reads the
+  investigators' reports, a plan reviewer reads the plan, and each owner
+  reads its own findings.
+
+Each member you add runs once and finishes. None of them sends work to
+another member. You make every call that changes the plan.
+
+## 4. Members you can add
+
+These profiles are a reference, not a sequence. Pick the ones the task
+needs. When you are unsure whether a member pays for itself, add it. One
+more member costs little. A misread task with nobody watching costs the
+whole run.
+
+| Member | Kind, model, effort | Use it when | It writes |
+| --- | --- | --- | --- |
+| analyst | investigator, opus, high | The task leaves room for more than one reading, or touches code you have not read. | `afk/understanding.md`, at most one page: the end state, the inferred acceptance criteria, what is out of scope, each ambiguity with the reading it chose, and the questions that decide the plan, grouped by area |
+| scout | investigator, opus, high | An area has questions that decide the plan and nobody has answered them. One scout per area, all in one `--add`. Keep scouts open until the build ends, so implementers can ask them directly. | its report: each answer with file:line |
+| planner | investigator, opus, xhigh | The work has more than one unit, open questions, or files that others read or pin. | `afk/plan.md` with a summary of at most 30 lines on top; `afk/decisions.md`; `afk/briefs/<role>.md` per implementer in the main skill's 14 sections; `afk/spec-wave<n>.json`; the result of each item of the main skill's planning check, using a temporary `git clone` where a fresh worktree is needed |
+| plan reviewer | reviewer, opus, xhigh | A plan exists and a wrong plan would waste more than one implementer's work. Fix the plan once from its findings, by reprompting whoever wrote it. Never review the same plan twice. | ranked gaps: a misread of the task, a criterion nobody can check, a file nobody owns, a check that misses what CI runs, a wrong shape |
+| implementer | implementer, opus, high | Code must change. | its branch |
+| reviewer | reviewer, opus, xhigh | A branch is finished. One per branch by default. Skip it only for a change so small that the closer's coverage check reads the whole diff anyway. | ranked findings |
+| closer | closer, opus, xhigh | Always, once code exists (section 2). | the integrated report and the exit codes |
+| reporter | investigator, opus, high | Always, at the end (section 7). | `afk/REPORT.md` |
+
+Use `max` only for one member whose task is hard to reason about, such as a
+race or a data-loss path. Set every `deadline_s` to 1.5 times what you would
+set otherwise. Write each brief to `afk/briefs/<role>.md` in the team
+directory. Tell every member that writes files outside its report file to
+put them under `afk/` in the team directory, never in the repository.
+
+Whoever settles an open question, a planner or you, writes it to
+`afk/decisions.md` in this form:
+
+    D3  2026-10-19 14:05  Which column marks an AFK team?
+    Chose: afk_budget_ends_at on the team row.
+    Why: one nullable column says both that the team is AFK and when its budget ends.
+    Reverse by: a schema migration that drops the column; only launch, status, close and the Stop hook read it.
+
+Each answer goes into the affected briefs under "Decisions already made". A
+brief has no "Open questions you must not answer" for work it must deliver.
+When a question cannot be settled from the task, the code or the docs, such
+as a credential nobody has or a product choice the task gives no hint of,
+cut the units that depend on it and list them as not done.
+
+## 5. Write down your roster before the first launch
+
+Before you add the first member, write entry `D1` in `afk/decisions.md`: the
+members you plan to add, the profiles you are skipping, and one line on why
+for each. When you change the roster later, add an entry. The reporter puts
+this in the report, so the user can see which checks the run skipped.
+
+## 6. While the team works
+
+- Answer a member's question in the turn it arrives. When the plan answers
+  it, point at the line. When a scout knows the area, tell the member to ask
+  that scout. Otherwise decide, and add a `D` entry. Never leave a question
+  `UNANSWERED`.
+- Send review findings to the branch's owner by path, all in one turn. Do
+  not sort the findings yourself: the owner checks each one against the
+  code, fixes what holds, and answers the rest with evidence. Allow at most
+  two fix rounds per owner. Never run the closer twice. Run
+  `teamwire verify <team> --role <owner>` after each fix round.
+- Make the integration branch `afk/<team>` off the base branch, and merge in
+  the plan's order. On a conflict, abort that merge. Reprompt the later
+  branch's owner to merge the earlier branch into its own branch and resolve
+  it, then merge again. Do not resolve conflicts yourself.
+- `TEAM-STALLED` is yours to handle. Run `teamwire status`, read the pane,
+  and replace the member once. If the replacement stalls too, cut the unit
+  and report it.
+- `teamwire status <team>` shows the time left in the budget. Launch the
+  last implementer no later than two thirds of the way through it, so the
+  review, the closer and the report still fit. Past the budget, launch
+  refuses new implementers. Finish what is running, verify it, and have the
+  reporter list the rest as not done.
+
+## 7. Report and close
+
+Add the `reporter` with the paths of whichever of these exist: `afk/task.md`,
+`afk/understanding.md`, `afk/plan.md`, `afk/decisions.md`, the closer's report, and the team's
+`reports/` directory. It runs `teamwire metrics <team>` for the cost, and
+gathers every member's **Decisions I made** list. It writes `afk/REPORT.md`
+in the team directory with these headings, in this order:
+
+1. **What you asked**: the task, quoted.
+2. **What I understood**: the end state from `understanding.md`.
+3. **The result**: the branch, its base commit, the commits, and how to try
+   it.
+4. **Verified**: each command, where it ran, and its exit code.
+5. **Decisions made for you**: the ones that most change the result, with a
+   pointer to `decisions.md`.
+6. **Not done, and why**.
+7. **Risks**: what you could not check, and what the reviewer or closer
+   flagged that is still open.
+8. **Cost**: wall time, and tokens per member.
+
+Run `teamwire close <team>`. Close refuses until the report has every
+heading, archives the team with the `afk/` files, keeps the branches and
+releases the sleep hold. When close refuses, reprompt the reporter with the
+missing headings. Then call `PushNotification` with the archived report's
+path if you have that tool.
+
+A run always ends with a report. When something fails that nobody can fix,
+have the reporter write up what exists. A partial result with an honest
+report is the goal. A session waiting for a person is the failure.
